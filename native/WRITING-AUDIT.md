# iPad 书写逻辑检查 · 2026-10-04

## 结论

当前画布用 UIKit Pencil 触点和自定义矢量笔带绘制，并用 PKDrawing 保存。已复现的断笔源于路径填充几何错误；另确认了实时分块漏更新、触摸取消丢笔迹、自动回复回调顺序、图标及颜色等问题。不是仅调整压感或稳定度能解决的情况。

## 已确认问题与修复

| 环节 | 原问题及影响 | 修复 | 证据 |
| --- | --- | --- | --- |
| 笔带填充 | 主体多边形与圆端点方向相反，nonzero 填充在叠加处抵消，出现空洞 | 统一路径方向 | 原直线用例出现 14 处缺墨；同一用例修复后通过 |
| 实时分块 | 每 64 段切换一次图层，但只更新最后一块；跨边界时前一块新增的段未发布 | 返回并更新所有受影响的分块 | 多次采样跨越三个分块，在连续位置检查无缺墨 |
| 系统取消 | touchesCancelled 只清空临时图层，整笔没有保存 | 取消时提交已采集的真实笔迹，移除预测尾迹；取消/强制结束不自动提问 | 检查统一 endStroke 的保存及回调路径；仍需 Pencil 真机取消事件验证 |
| 属性修正 | 压力/位置估算修正会删除全部实时图层、重建整笔 | 按受影响的触点更新相关分块；图层更新禁用隐式动画 | 分块边界修正测试通过；真机时延尚未测量 |
| 采样与预测 | 空 coalesced 数组可能漏掉事件；预测触点未筛掉过期时间 | 空数组回退当前触点；合并触点按时间排序，预测仅使用未来触点；正常抬笔补当前触点 | 代码路径检查、圆点/重复触点/反向书写测试通过 |
| 自动回复 | 正常抬笔先启动计时，随后 drawingDidChange 又将计时取消 | 先发布笔迹更新，再发送结束事件；晚到的属性修正重置计时 | 回调与协调器代码检查；以前算法测试未覆盖这个顺序 |
| 工具图标 | 钢笔使用未经验证的 pen.tip，缺少缺失图标回退 | 钢笔改用 pencil.tip，圆珠笔/画笔使用独立图标；UIKit 取不到图标时回退 pencil | 工具符号在宿主系统逐个检验通过；原生编译通过 |
| 高光颜色 | 落笔时无条件换成 systemYellow，用户颜色选择没有进入笔迹 | 按工具框选色写入实际 PKInk | 检查颜色从 store 到画布、保存、恢复的完整链路 |
| 页面手势 | 防误触时禁用全部 PDF 手势，影响范围过大；同值设置反复执行 | 仅暂时抑制平移/缩放，排除导航对 Pencil 的识别；同值状态不重复更新 | 代码检查；手掌先落、悬停、缩放后的连续书写仍需真机验证 |
| 橡皮 | 只检查采样点，快速擦除可能跨过细笔画而未命中 | 检查橡皮扫过的线段与笔迹距离 | 两端远离笔迹但中间相交的用例通过 |

## 正常书写链路

Pencil 落笔冻结本笔工具、颜色、粗细和稳定度 → 合并真实触点 → 稳定滤波和压感宽度 → 贝塞尔笔带与分块渲染 → 预测尾迹临时显示 → 正常抬笔提交真实点 → 更新修订号和本地保存 → 启动停笔计时 → 本机识别 → 自动问 AI。

预测点不写入 PKDrawing 或识别图像。橡皮仍整笔删除并按一次手势撤销；取消擦除恢复手势前笔迹。已发送笔画按书籍、页码排除，继续书写不把上一句再次提交。

## 核验与边界

24 项原生回归测试通过，覆盖几何填充、跨分块连续性、估算点修正、重复点、反向笔画、压感、稳定、快速橡皮、分组、自动计时状态与工具符号。模拟器与真实 iPad 设备架构的无签名构建均通过。未调用付费 AI。

编译和几何测试不提供真实 Apple Pencil 延迟、系统取消频率或手掌误触的结论。需要在 iPad 上复测：长直线/连续圈画是否缺墨、书写中手掌落下是否取消、不同缩放与页面边缘是否对齐，以及停笔后的实际自动回复。

剩余性能观察点：正常抬笔仍构建整笔最终路径；撤销仍可能重建整页图层；PDF 上下文裁剪与图像准备仍在主线程。这些可能影响大页面或大量笔迹的响应，但本次没有设备性能数据，不能将其断言为用户断笔的原因。已减少最频繁的实时属性修正重建。
